# Security policy

## Reporting a vulnerability

Please use the repository host's private vulnerability-reporting feature when it
is available. If it is not available, open a minimal public issue asking for a
private contact channel without including technical exploit details.

Do not post passwords, private keys, server fingerprints, hostnames, backup paths,
personal filenames, screenshots containing account details, or other sensitive
data in an issue.

Include the affected PiffBackup version, Android version, device architecture,
and the smallest safe reproduction description. Reports involving destructive
remote behavior should use a disposable test destination containing no personal
data.

## Supported versions

PiffBackup is currently preparing its first public release. Security fixes apply
to the latest published version only.
